# 原始数据字典

## 使用原则

所有以 `_raw.csv` 结尾的文件都是“原始收集层”。工具只把存档记录展开为表格，不替学生定义研究变量或完成汇总。`source_file`、`game_version`、`game_date`、`country_id`、`country_tag` 用于追溯每一行来自哪份存档。

## 各原始表

### `game_definition_files_raw.csv`

从学生设备的 `Victoria 3/game/common` 读取相关定义文件，每个文件一行，保存所属定义组、相对路径、字节数、SHA-256、解析状态和顶层定义键数量。它证明本次解释存档时使用的是哪一套游戏规则文件。

### `game_definition_keys_raw.csv`

把建筑、商品、法律、机构、生产方式、科技等定义文件中的顶层键逐行保留。例如 `building_iron_mine`、`institution_social_security`。这是游戏定义原始层，不包含工业篮子标签或研究变量。

### `game_environment.json`

记录实际找到的游戏安装目录、`game/common`、`game/localization`、Steam build ID、Steam版本字段以及全部相关定义文件的合并指纹。每份存档在 `manifest.json` 中还会记录是否与本机版本一致。

### `save_metadata_raw.csv`

每份存档一行。保存原文件名、SHA-256、字节数、存档格式、游戏版本、游戏日期和国家ID等信息。这里的哈希和文件大小是溯源信息，不是研究变量。

### `country_scalar_fields_raw.csv`

国家节点中的直接标量字段，一行一个字段。`source_section` 表示来自 `country.pop_statistics` 还是 `country.budget`；`field_name` 是存档字段名；`raw_value` 是原值。例如存档若直接提供 `population_radicals`，这里保留人数原值，但不会计算其人口占比。

### `country_trend_values_raw.csv`

保存 GDP、平均生活水平和识字率趋势节点中全部已存数值及其位置。工具不替学生挑选“最终值”，学生需先理解 `channel`、`channel_date`、`stored_index`、`value_position` 后再决定使用规则。

### `budget_slots_raw.csv`

保存收入和支出数组的每个槽位。`direction` 区分 income/expense，`slot_index` 是原数组位置，`raw_value` 是原值。工具不计算总收入、总支出或净余额。

### `pop_records_raw.csv`

比利时境内每条人口记录一行，保留人口类型、州、劳动力、家属、工作建筑ID、识字人数、财富、上一期生活质量、社会阶层等直接字段。

`loyalists_and_radicals` 是存档中的带符号原值：正数表示效忠派，负数表示激进派。工具不把它拆成全国人数，也不计算比例。

### `building_records_raw.csv`

比利时境内每条建筑实体一行，包含建筑ID、州、建筑类型、等级、staffing、建立日期、财务与生产方式等直接字段。所有建筑类型都会保留，不附加工业篮子标签，也不按类型或州求和。

建筑就业人数不在这里提前计算。后续可用 `pop_records_raw.csv` 的 `workplace_building_id` 对应本表 `building_id`，再按研究方案汇总 `workforce`。

### `state_records_raw.csv`

每个比利时州一行，保存基础设施、基础设施使用量、土地等直接字段，并保留 `raw_record_json` 供追溯。

### `state_pop_statistics_raw.csv`

各州 `pop_statistics` 中的直接标量字段，一行一个字段。工具不做全国加总或跨州平均。

### `institutions_raw.csv`

保存比利时所有机构记录及 `investment` 原值。社会保障、工作场所安全等实际等级需要学生依据锁定的操作定义，从这里筛选或核对。

### `laws_raw.csv`

保存比利时的法律记录、是否active、启用日期、替代关系和原始JSON。工具不判断哪条法律应被归入“高/低社会保护”。

### `construction_queue_raw.csv`

保存存档当时仍在政府或私人建造队列中的项目。`construction_left` 是剩余工程量。队列只能说明保存时正在建什么，不能证明已经建成，也不是历史累计建设记录。

### `errors.csv`

逐文件记录导出失败原因。只有表头表示没有逐文件失败。

## 留给学生在数据处理阶段计算的内容

以下均不由导出工具生成：

| 待构造变量 | 可用原始数据举例 |
|---|---|
| 全国总人口、总劳动力 | `pop_records_raw.csv` 中 `workforce`、`dependents`，并与存档直接统计字段交叉核对 |
| 激进派人数与激进派比例 | 国家直接统计字段或人口记录的带符号原值；比例需再除以学生锁定的人口分母 |
| 工业篮子建筑等级 | 学生先锁定篮子清单，再从 `building_records_raw.csv` 筛选并汇总 `levels` |
| 工业篮子就业及占比 | 先按建筑ID连接人口表与建筑表，再筛选篮子并定义分母 |
| 各类建筑、各州建筑总量 | 对建筑原始记录自行分组汇总 |
| 阶层生活水平差距 | 按锁定公式使用社会阶层、人口权重与生活质量候选字段计算 |
| 前后变化、增长率 | 按 `source_file`/`game_date` 对齐观察点后计算 |
| 财政净余额 | 先确认预算槽位含义，再依预登记公式计算 |

所有公式、篮子清单、缺失值规则和单位都应另存在学生的数据处理脚本或分析说明中，不要覆盖 `_raw.csv`。
