# 第04部分：合并原始导出表

目前用途：用 SL_01、FL_01 两组不完整数据测试整合流程。测试成功不代表正式样本完整，也不代表第05部分的数据质量验收已完成。

## 输入与运行

需要 Python 3.11 或更新版本。整合脚本只用 Python 标准库，不需要安装导出工具的依赖，也不需要重新运行游戏。

将解压后的导出包保留在以下结构中；已有的原始 CSV 不修改：

```text
data/raw/
  SL_01/V3_raw_export_日期_时间/manifest.json
  SL_01/V3_raw_export_日期_时间/game_environment.json
  SL_01/V3_raw_export_日期_时间/raw_data/*_raw.csv
  FL_01/V3_raw_export_日期_时间/...
```

运行组别由 `data/raw` 下一级目录确定，不根据 `autosave.v3` 这种重复文件名猜测。James 已确认早一批自动存档、LL 命名存档属于 SL_01。其他六组以后同样使用 SH_01、SH_02、SL_02、FL_02、FH_01、FH_02 目录。

在仓库根目录运行：

```console
python scripts/merge_raw_exports.py --mode pilot
```

也可以指定外部原始数据目录：

```console
python scripts/merge_raw_exports.py --mode pilot --input-root "外部原始数据目录"
```

默认在 `data/interim/pilot_运行时间/` 新建输出文件夹。`--output` 可以指定仓库 `data/interim` 下尚不存在的文件夹。脚本不覆盖以前的结果，不覆盖输入，不自动解压或重复读入旁边的 ZIP。新输出与输入目录不能互相包含。

## 实际合并什么

先按 manifest 检查包状态，再读取固定的13张 `_raw.csv`，逐表纵向合并。输出文件名使用 `_merged.csv`。包括存档身份、全部建筑、人口、国家标量、趋势、预算槽位、州、州人口统计、机构、法律、当前队列，以及两张游戏定义表。

每行增加 `run_id`、`speed_assignment`（S/F）、`protection_assignment`（L/H）、`replicate`、`definition_fingerprint`。另有源包相对路径、manifest 哈希、源 CSV 哈希、源存档哈希和 CSV 行号。源存档哈希来自导出 manifest，本步骤不宣称重新核验外部 `.v3` 文件。

游戏定义表是“每个导出包”的资料，本来没有观察日期或源存档；保留其包级来源，不伪造观察点。不把各包重复的定义键当作人口或建筑记录。建筑表保留全部类型，不先删掉工业篮子以外的建筑。

## 明确的数据处理规则

| 问题 | 本脚本的处理 |
|---|---|
| 日期格式 | 合并表的 `game_date` 统一为 `YYYY-MM-DD`；原始日期及小时完整保留在 `game_date_raw`。其他原始日期字段原样保留。 |
| 1月1日与12月31日 | 不互相替换。当前配置保留原方案1836—1860年每年12月31日的计划，用来报告差异；正式使用前两人确认计划。 |
| 起点或非年度日期 | 测试模式保留，并标为 `baseline` 或 `off_schedule`，不会算成一个合格的年度计划点。 |
| 数值 | 对配置中明确的数值列验证能否转成有限十进制数；输出仍保留原文本精度。异常数值报错，不填成0。混合类型的国家标量 `raw_value` 不强制转数字。 |
| 空白、NA、0 | 三者原样保留，不互换。导出工具已经填入的默认0无法由整合脚本还原成缺失，后续仍需回查源存档。 |
| 同名自动存档 | 用组别、源包、文件名及哈希追溯；不同年份同名文件不会互相覆盖。 |
| 相同日期的重复存档 | 同一组同一日期且存档 SHA-256 相同，只计一份，并在清单中记录副本。若 SHA-256 不同，测试模式隔离该日所有候选，等待明确选择；完整模式报错。 |
| 表内重复行 | 按配置定义的主键识别；发现重复直接报错，不偷偷删行。实体主键含组别、日期、国家及实体ID；键值说明见配置。 |
| 版本与列变化 | 工具版本锁定1.2.0、游戏版本锁定1.13.10。缺列、多列、列次序变化均报错；不自动填列或混合不同版本。 |
| 失败导出包 | 测试模式隔离整包，包括其中成功的文件，避免半导出数据进入合并；完整模式报错。原包保留。 |
| 定义指纹 | 合并的包必须一致；检查定义解析状态，并从定义文件哈希清单复算总指纹。 |
| 来源与分析列 | 新增来源列仅用于溯源；只保留研究变量的原始组成字段，不计算工业篮子、激进派比例、阶层差距或净余额。 |

这些是本次测试的显式处理规则，写在脚本和 `config/raw_merge_rules.json`；它们不代替两人对正式研究公式与日期计划的共同确认。

## 输出与排错

- `merge_summary.json`：成功/失败、模式、纳入的组别与存档数、脚本哈希。读取下游数据前先确认 `status=success`。
- `merge_stats.csv`：每张表各组的行数、列数和实际日期范围。
- `source_inventory.csv`：所有扫描到的存档、哈希、纳入/排除决定及原因。
- `merge_warnings.csv`、`merge_log.txt`：日期差异、重复副本、隔离包及运行结果。
- `input_hashes.csv`：本次读取的输入文件哈希；运行结束复核输入未变。
- `rules_used.json`：本次实际使用的规则副本。

出错返回非零退出码，结果目录中的状态写为 `failed`。此前可能已写出的部分表只供排查，不能当成功结果；原输入始终保留。

`--mode full` 要求八组日期完整匹配，并对失败包、版本不匹配和冲突日期报错；它仍不验证实际福利等级、人口合理性、实验操作偏离等第05部分内容。因此本脚本不会把 `formal_sample_ready` 设为 true。

## 验证脚本

```console
python -B -m unittest discover -s scripts -p "test_merge*.py" -v
```

测试覆盖跨组合并、源文件不变、空白/NA/0、同名不同日期、相同存档副本、冲突日期、失败包、版本与指纹差异、列变化、异常数值、重复实体，以及不完整数据不得通过完整模式。
