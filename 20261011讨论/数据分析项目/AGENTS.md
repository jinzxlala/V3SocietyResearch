# Victoria 3 研究分析：AI 协作约定

## 先了解任务
开始工作先读取同目录 `当前研究进展背景.md`，再读取 Notebook Part 1 的最新共识。背景文件区分了 Google Docs 的已列定规则、后续确认、真实数据和待核对冲突；不要用通用方案或旧记忆覆盖它。工业篮子已有 12 类约定，X_actual 已有就业占比变化等候选；学生应核查并确认具体实现，不是从空白重新设计。日期、H 实值、F 队列等冲突未经确认不得宣布解决。

学生是已学过数据清洗、EDA、特征工程、基础建模、评估与 AI Coding。不要重讲基础课，也不要替他们完成研究决策。今天用 FL_01、SL_01 完成第一版分析；将来同一程序要接入 SH、FH 及其他重复运行。

本次主线：实际工业扩张是否不同？低社会保护条件下，FL 与 SL 的激进派占比怎样变化？这些描述性差异是否受指标定义、领土变化或事件影响？

`课堂操作指引.md` 与投影页是同一套学生操作说明：每一步的原始表、字段、关联、讨论事项和交付位置都在其中。学生不清楚下一步时，定位到当前 Part，解释一个具体动作；不要只重复“做 EDA”“构造特征”。其中公式是讨论候选，虚构示例不是真实结果，文件结构示例也不构成研究口径确认。

## 目录与运行
- 从本项目根目录启动 Jupyter，打开 `01_研究分析.ipynb`。也可以使用 VS Code 的 Jupyter 扩展，选择有依赖的 Python 内核。
- `data_raw/FL_01/`、`data_raw/SL_01/` 完整保留原始导出目录。各自的 CSV 在 `raw_data/` 中；字典、manifest、环境说明、验证报告与日志仍在原位。
- 原始目录只读，不重命名、不修正、不覆盖其中的文件。新结果写入 `data/processed/`；图表写入 `outputs/figures/`；汇总表写入 `outputs/tables/`。
- `requirements.txt` 是可选的环境补充。先检查现有环境；缺少时在本项目虚拟环境执行 `python -m pip install -r requirements.txt`，不要更改系统 Python。
- 使用相对路径，兼容 Windows/macOS；程序按需创建输出目录，不依赖 Git 保存空文件夹。不要把老师电脑的安装路径当依赖。CSV 已导出，分析阶段不需要安装或启动游戏。
- Notebook 是空框架，没有答案代码。允许学生按需要增加代码格、Markdown 说明和辅助脚本。不要一次性填满所有 Part。

## 课堂计时前

- 打开 Notebook，选好 Python 内核，确认能导入 pandas、numpy、matplotlib、seaborn，能读取两组 CSV 表头。依赖缺失在开始计时前解决，检查代码不作为预填的分析答案。
- 120 分钟从 Part 1 的指标讨论开始，不包含首次安装环境和背景预读。

## 先讨论，再写特征构造代码
收到“开始分析”时，先检查 Notebook 的 Part 1 是否有双方确认的指标方案。没有时，读取表头、核查原始字段、提出候选口径可以进行；不得直接选定并计算研究特征。
对于尚未决定的项，最多提出 2–3 种合理选择，说明它们测量的含义与局限，请两位学生决定。学生确认后，记录决定并只实现当前任务。不要求每条语句都重新确认。

Part 1 可以先留下指标讨论稿；Part 2 读取真实字段后补齐具体来源和缺失规则。每个指标在计算前都应由双方确认，不要求未核验的其他指标先全部解决。字段的真实含义与革命后的国家身份需要证据，不能通过两人选择来代替核验。

每个指标至少记：含义、来源字段、统计范围、公式、单位、缺失处理、主指标/补充指标。已有实验协议优先；课堂新增定义注明形成日期。实际尚未查看组间结果时可以先登记分析口径，但不得事后伪称“实验前预注册”。

### 本次必须覆盖的指标
1. **人口与政治结果**：每个观察点的总人口、激进派人数、激进派占比。讨论人数来源、分母、统计范围、比例单位（0–1 或 0–100）及缺失规则；必须交叉核对。
2. **工业化基础量**：使用 `工业篮子建筑键对照.md` 核对既定 12 类建筑，讨论并保存统计范围；形成该范围的建筑等级总量、就业人数及所选就业分母。原始导出覆盖所有建筑，不要根据预期结果改篮子。
3. **实际工业化变化 X_actual**：从建筑等级变化、工业就业占比变化、工业就业增长等候选中确定主指标与至少一个可计算的替代指标。讨论基期/相邻期、时间跨度、零分母与单位。就业分母须说明是否排除失业人口；不能直接把总劳动力叫总就业。
4. **社会保护实际状态 W**：分别保留社会保障和劳动保护相关有效法律、两项对应机构的实际等级或核验状态。不要未经讨论合成总分；缺少机构行不自动等于 0。
5. **可比性与事件标记**：run、条件、真实日期、基线/年度/事件记录类型、纳入州范围与变化、可核实的革命等事件。没有事件记录不表示没有发生。
6. **run 层面的比较量**：在共同且明确的观察窗口汇总政治结果的平均水平、峰值与日期、首末变化，并汇总工业化变化。讨论基线是否计入均值；额外事件点不得让某年获得额外权重。

**研究后续仍需关注**：阶层生活水平及其差距 M。先核实当前生活水平字段和权重；`wealth` 与 `previous_quality_of_life` 不自动等于当前 SoL。能验证则计算，不能验证则列出具体缺口并继续主分析。GDP、财政、州动乱为补充；找不到可靠字段时不得猜测。

## 数据处理必须守住的边界
- 先读每组数据字典、导出说明与 CSV 表头。定义表中的键可以辅助理解，但不等于已验证全部字段语义。导出验证通过不等于研究变量有效。
- run 身份必须来自所属目录/清单；`01` 在 FL、SL 中都会出现，不能单独当唯一 run_id。
- 跨表关联至少限定 run + source_file/同一存档 + 国家，再使用实体 ID；不能跨年份直接连接 pop_id、building_id 或 state_id。验证多对一关系，防止连接后重复加总。
- 每组有 25 个固定日期：1836-01-01 至 1860-01-01，含基线；不是 25 个后续年末点。FL 另有事件存档，不算第 26 个年度点。保留原始日期，分析日期另建；四段式日期末段不可直接当公历日期部分。
- 文件名日期和内部日期可能不同，按内部日期建分析键并保留冲突；不要默默修改源文件。
- 两次运行的领土变化时间不同。用州表检查各日期范围、标注首次观察到的变化；不能把它说成已知确切发生日期。固定共同州范围可作敏感性分析，不代表排除了全部混淆。
- 国家统计激进派人数与逐人口记录汇总可能不一致。比较两种来源的差异，查语义、日期、范围，必要时向学生索取游戏界面核验；不得取平均“消除”差异，不得静默截断不合理值。
- 本批数据已发现两种政治人数来源不一致、部分人口政治原值绝对量超过该行人口、基线缺少国家激进派字段。缺行不等于零。若到 Part 3 仍需界面或导出语义证据，向老师说明具体字段、样例和所需证据；未验证的 Y 不进入正式比较结论。继续完成已验证的工业化、条件核查和敏感性分析，并记录待补证任务，不把整个分析停掉。暂定口径也须双方与老师明确确认、标注限制，不能当作核验通过。
- `loyalists_and_radicals` 是带符号原值，正为效忠派、负为激进派。负数不一定是错误。若政治人数超过对应人口，需要保留并查原因，不能自行裁剪。
- 缺失、合法零值、制度未设立和导出失败分开处理；不得为画图填 0 或制造观测。
- 建筑 `levels` 是等级，不是实体行数；`staffing` 不经核验不能当就业人数。建造队列仅是当时未完成项目，不是累计建设或已建建筑。
- 不从建筑所在地/所有权直接推断当初由谁建造；境内私人或外国投资造成的扩张保留在实际结果中。
- 趋势表含重叠历史片段，不能直接选 CSV 最后一行作为当前 GDP 或平均全部历史值。预算 `credit` 不直接等于债务。
- 不将整份原始数据发送到外部 AI 服务；辅助排错只提供必要的表头和去除个人、机器路径等信息的少量样例。GitHub 协作按下节规则执行，不将本条理解为禁止全部代码推送。

## 实现与解释
- S/F 是预设实验条件，X_actual 是运行后的实际指标。不得按 X_actual 大小重新分配 S/F，或把 X_actual 与 Y 的相关直接称为处理效应。
- 当前仅 FL、SL 各一次。只作两条轨迹的描述性比较，不能检验社会保护调节作用；年度行不独立，不拿 25 年当 25 次实验做 t 检验或显著性回归。
- 共同起点复制不自动产生独立重复。未来 8 个 run 也要先核查独立性/配对依据，再决定推断方法；不能按编号直接假设配对。
- 图表写明范围、单位、有效日期数、基线处理；方法变化保留原因和原结果，不因更符合假设而替换指标。
- 每次 AI 写完代码，应说明输入、输出、采用的已确认规则及一个核对办法。两人交叉检查至少一个日期。学生负责判断，AI 不替他们宣称“已经理解”或编造共识。
- 输出 run-date 分析表与 run 汇总表；用条件配置组织数据，不把程序写死为两组。新组使用同一规则，缺失项如实报告。
- 本次统一交付位置：`data/processed/analysis_panel.csv` 为年度分析表，`data/processed/event_records.csv` 保留额外事件（若有），`outputs/tables/run_summary.csv` 为每 run 一行的汇总，图保存在 `outputs/figures/`。分析表保留基础量、人数来源、单位约定、日期/范围及核验状态；列名可协商，不用未核验数字填满表格。两条工作线在同 run、同 source_file、同 country_id 下对齐，并检查 date；年度面板再验证 run_id＋date 唯一。
- 后续可计算低保护差 FL−SL、高保护差 FH−SH，再比较二者。必须使用同一指标、窗口、单位与预先说明的汇总规则；该差异本身不保证因果解释。
- 结束前 Restart & Run All，确认从只读原始数据重建已验证部分的结果；未验证项保留状态，不假称全部完成。按上述 GitHub 边界检查暂存差异和 Notebook 输出，再提交或报告待推送状态。
