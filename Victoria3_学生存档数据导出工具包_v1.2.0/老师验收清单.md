# 老师验收清单

## 一、先验收来源与运行结果

- [ ] `manifest.json` 中 `tool_version` 为全班统一版本；
- [ ] `data_contract` 为 `raw_only`；
- [ ] `game_environment.json` 记录了实际游戏目录、Steam build和定义指纹；
- [ ] `game_definition_files_raw.csv` 全部为 `parse_status=success`；
- [ ] `game_definition_keys_raw.csv` 包含建筑、商品、法律、机构、生产方式和科技定义；
- [ ] `successful_files` 等于本次应提交的存档数；
- [ ] `failed_files` 为0；
- [ ] 每份存档都有SHA-256、游戏日期、游戏版本和格式；
- [ ] 同一批正式run的游戏版本一致；
- [ ] 每份正式存档的 `definition_version_match` 为 `true`；若为 `false`，不可直接用当前定义解释；
- [ ] 学生另行保留或上传了对应原始 `.v3`；
- [ ] 学生保留了版本、checksum、DLC/mod状态截图。

## 二、再验收原始表是否齐全

- [ ] `raw_data` 中包含数据字典列出的全部 `_raw.csv`；
- [ ] `save_metadata_raw.csv` 的日期与文件名/观察点相符；
- [ ] `building_records_raw.csv` 含多种非工业篮子建筑，没有只导篮子；
- [ ] `pop_records_raw.csv` 保留 `workforce`、`dependents`、`workplace_building_id`、`loyalists_and_radicals` 等原始字段；
- [ ] `institutions_raw.csv` 和 `laws_raw.csv` 可追溯W的实际状态；
- [ ] `construction_queue_raw.csv` 用 `queue_kind` 区分政府与私人队列；
- [ ] 空值没有被学生改成0；
- [ ] 原始表没有被学生手工覆盖。

## 三、检查是否越过了“只导出”边界

本版工具不应生成以下分析结果：

- [ ] 没有 `project_summary.csv`；
- [ ] 没有 `building_by_type.csv` 或 `building_by_state.csv`；
- [ ] 没有 `basket_*` 汇总或篮子标签；
- [ ] 没有激进派/效忠派比例；
- [ ] 没有阶层加权均值、差距、增长率或财政净余额。

若学生另有分析文件，应与 `_raw.csv` 分开保存，并提交可重复执行的公式或代码。版本不一致、日期错误、W未达目标或操作偏离协议的存档仍可作为技术记录，但不能自动计入正式样本；不要为了“通过验收”修改原始CSV。
